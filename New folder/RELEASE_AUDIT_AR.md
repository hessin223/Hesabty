# تقرير مراجعة حسابتي قبل الإصدار

## ما تم التحقق منه
- اختبارات محرك الحسابات: `node --test tests/ledger.test.mjs` نجحت 13/13 في بيئة المراجعة.
- المستودع المضغوط لا يحتوي على `package-lock.json`، كما أن مجلد `.git` الموجود في الأرشيف غير صالح للاعتماد عليه (مرجع HEAD يشير إلى كائن غير موجود). لهذا تم حذف بيانات Git المضمنة من حزمة التسليم؛ تُرفع ملفات المصدر إلى GitHub ثم ينشأ سجل Git صالح هناك.
- واجهة الإصدار الأصلي كانت تعرض عنصرًا عامًا لمعظم الوحدات بدل واجهات تشغيل حقيقية.

## تحسينات هذه النسخة
- إضافة سجل عمليات مالي قابل للاستخدام مع البحث وتصفية النوع والحساب وإلغاء العملية مع الاحتفاظ بسجلها.
- إضافة واجهة فعلية لإضافة التصنيفات الهرمية.
- إضافة تصدير نسخة احتياطية JSON واستعادة مع تأكيد صريح.
- إضافة شاشة ملخص تقارير حسب الفترة.
- إضافة إعدادات عامة وقسم المشاريع الأساسي.
- تحسين الرئيسية بإظهار آخر العمليات وحالة البداية الفارغة.
- عرض ملخصات صادقة للأقسام التي لا تزال تحتاج نماذج CRUD كاملة، بدل الادعاء بأنها مكتملة.
- تعديل إعداد Workflow لاستخدام Java 17 وإزالة اعتماد إعداد Node على ملف قفل غير موجود.

## ما لم يتم التحقق منه
- لم يُبنَ APK داخل بيئة المراجعة لأن اعتماديات npm غير متاحة محليًا ولا يوجد اتصال بسجل npm.
- لم يتم دفع هذه النسخة إلى GitHub، ولم يتم التحقق من تشغيل GitHub Actions.
- وحدات العمال والمخزون والمشتريات والأصول والمهام والإقفال والمرفقات والتحويشة ما زالت تحتاج استكمال واجهات CRUD كاملة واختبارات قبول منفصلة.
- تخزين البيانات في المتصفح منفصل عن قاعدة SQLite الأصلية في Android. لا تفترض أن بيانات المعاينة ستنتقل تلقائيًا إلى APK.

## الخطوات المقترحة قبل استخدام بيانات مالية حقيقية
1. رفع ملفات المصدر إلى مستودع Hesabty.
2. تشغيل GitHub Actions وفحص سجل البناء.
3. تنزيل APK من Artifacts وتثبيته على الهاتف.
4. اختبار إنشاء حساب، تسجيل دخل/مصروف، تحويل، إغلاق التطبيق وإعادة فتحه، ثم تصدير واستعادة نسخة احتياطية.
5. لا تعتمد على الأقسام التي يظهر فيها تنبيه بأنها تحتاج استكمالًا.
